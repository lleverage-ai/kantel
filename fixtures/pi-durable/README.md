# Pi Durable recordings

Raw recordings of Pi Durable's `watchEvents()` stream: what the session host receives from Pi, before Kantel projects
it onto its client protocol. The console's fixture host never reads these directly. `apps/console/scripts/project-fixtures.ts`
projects each one into a protocol-frame fixture of the same name in [`../sessions`](../sessions).

Pinned to **earendil-works/pi@973b74c55fcf096ad5976f8d8850c147ee2e62d4**. The event and message shapes come from that
commit's `packages/durable/src/harness/events.ts` (`AgentEvent`, `SnapshotEvent`), `packages/durable/src/entries.ts`
(entry kinds) and `packages/ai/src/types.ts` (messages). The types are in `apps/console/src/pi-durable/events.ts`.
When Pi's events change, update those types, re-pin here and in each recording's header line, and regenerate.

## Format

JSON Lines. Line 1 is a header, `{ "recording": "pi-durable/watchEvents", "pi": { "repo", "commit", "package" }, "title" }`.
Each later line is one `watchEvents()` batch, `{ "seq", "at", "events" }`: `seq` is the batch's place in the stream (0 for
the opening snapshot), `at` is milliseconds since the recording started, and `events` are Pi's, unchanged.

## Files

- `small.jsonl`: hand-written. Two runs, one with a tool call and one long streamed answer. Committed.
- `long-2000.jsonl`: generated by `apps/console/scripts/generate-fixture.ts` (deterministic, seeded). A snapshot with
  1,999 completed runs, then a live run that ends in a long Markdown answer. About 3.6 MB, so it's gitignored and
  generated before `dev`, `build` and `test`; `pnpm fixtures` in `apps/console` makes it and its frames by hand.
